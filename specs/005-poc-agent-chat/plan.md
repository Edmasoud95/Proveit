# Implementation Plan: POC Agent Chat UI

**Branch**: `005-poc-agent-chat` | **Date**: 2026-05-27 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/005-poc-agent-chat/spec.md`

## Summary

Add a Chat tab to each POC that lets the developer send messages to the configured agent and see streaming responses with inline tool call traces and markdown rendering. The backend exposes a new SSE endpoint that calls the POC's configured LLM provider; the frontend renders the thread using `@assistant-ui/react` with `useExternalStoreRuntime` to own message state and integrate with the existing streaming infrastructure.

## Technical Context

**Language/Version**: TypeScript 5.x strict mode
**Primary Dependencies**:
- Backend: NestJS 10, OpenAI Node.js SDK (existing), RxJS (existing)
- Frontend (new): `@assistant-ui/react`, `@assistant-ui/react-markdown`
- Frontend (existing): React 18, TanStack Query 5, Tailwind CSS 3

**Storage**: No new storage. Chat history is session-only (React state).
**Testing**: Vitest + React Testing Library (frontend), Jest (backend)
**Target Platform**: Web browser (same as existing app)
**Project Type**: Web application — monorepo with existing backend + frontend packages
**Performance Goals**: First token appears within 2s of message submission (SC-001)
**Constraints**: Must integrate with existing LLM routing (`resolveForTask`), existing SSE pattern, existing nav structure. No new Prisma migrations.
**Scale/Scope**: Single-user POC tool; single active chat session per POC per browser tab.

## Constitution Check

| Principle | Status | Notes |
|---|---|---|
| I. Speed Over Completeness | ✓ Pass | Session-only history; no persistence complexity |
| II. AI-Assisted Not AI-Replaced | ✓ Pass | Chat is a direct test interface, not a hidden abstraction |
| III. Local-First | ✓ Pass | Uses existing `resolveForTask('agent')` — defaults to local LLM |
| IV. Portable Configs | ✓ Pass | No new config format introduced |
| V. Minimal Dependencies | ⚠ Justified | 2 new packages: `@assistant-ui/react` + `@assistant-ui/react-markdown`. Explicitly requested by user; replaces ~500 lines of custom streaming chat + markdown state management. |
| VI. UI/UX First | ✓ Pass | purpose-built chat UX; streaming cursor, accessible input, tool traces |
| VII. Progressive Disclosure | ✓ Pass | Tool calls collapsed by default; expand on demand |
| VIII. Immediate Feedback | ✓ Pass | Streaming response; disabled input during generation |
| IX. Opinionated Defaults | ✓ Pass | Chat uses agent routing default; no model selector needed in chat view |
| Architecture: Frontend → Backend only | ✓ Pass | Frontend calls `/api/pocs/:id/chat/stream`; backend calls LLM |

**Violation Justification (Principle V)**:

| Violation | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| `@assistant-ui/react` | Streaming thread state, message rendering, tool call lifecycle, accessible composer | Building equivalent from scratch = ~300 lines of complex React state + SSE wiring. User explicitly mandated this library. |
| `@assistant-ui/react-markdown` | Streaming-safe markdown rendering (no flicker during token arrival) | `react-markdown` standalone requires custom assistant-ui integration bridge |
