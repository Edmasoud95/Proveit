# Implementation Plan: Multi-Provider LLM with Per-Task Model Routing

**Branch**: `004-multi-provider-llm` | **Date**: 2026-05-27 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/004-multi-provider-llm/spec.md`

## Summary

Replace the single `LlmConnection` per POC with a multi-provider model. Add a `TaskModelOverride` table for per-task routing. Expose new CRUD endpoints for providers and routing config. Rewrite `LlmConnect.tsx` with progressive disclosure — provider list always visible, advanced routing panel collapsed by default. Preserve full backward compatibility for existing POCs via a data migration that promotes existing connections to default providers.

## Technical Context

**Language/Version**: TypeScript 5.x (strict mode), Node.js 20  
**Primary Dependencies**: NestJS 10, Prisma 5, OpenAI Node.js SDK, React 18, TanStack Query 5, Tailwind CSS 3  
**Storage**: SQLite via Prisma 5 — schema migration removes `@unique` from `LlmConnection.pocConfigId`, adds `name`/`isDefault`/`availableModels` fields, creates `TaskModelOverride` table  
**Testing**: Existing test setup (backend: Jest via NestJS; frontend: Vitest)  
**Target Platform**: Local dev (Mac/Linux), same as existing  
**Project Type**: Monorepo web application (NestJS backend + React frontend)  
**Performance Goals**: Provider list and routing config load in <200ms (single DB query); `resolveForTask` adds <5ms overhead to eval runs  
**Constraints**: No new npm packages; API key never surfaced in plaintext; backward compat for all existing POCs  
**Scale/Scope**: 2–4 providers per POC typical; 4 task types; 1 routing override per task type

## Phase 0: Research

See [research.md](research.md) — all decisions resolved.

**Key decisions**:
1. Remove `@unique` from `LlmConnection.pocConfigId` (table recreation migration, existing rows preserved)
2. Separate `TaskModelOverride` table with `onDelete: Cascade` for automatic override cleanup
3. `resolveForTask(pocId, taskType)` single resolution method; callers don't need to know routing rules
4. New `/providers` + `/routing` endpoints; old `/llm` endpoints kept as compat shims
5. `LlmConnect.tsx` rewritten in three sections: provider list, add/edit form, collapsible routing panel

## Phase 1: Design & Contracts

### Data Model

See [data-model.md](data-model.md) for full schema diff and migration strategy.

**Summary of changes**:
- `LlmConnection`: remove `@unique` on `pocConfigId`; add `name`, `isDefault`, `availableModels`; add `@@index([pocConfigId])`
- `TaskModelOverride`: new table with `@@unique([pocConfigId, taskType])` and `onDelete: Cascade` on both FKs
- `PocConfig`: `llmConnection LlmConnection?` → `llmConnections LlmConnection[]`; add `taskModelOverrides TaskModelOverride[]`
- Migration data step: `UPDATE LlmConnection SET isDefault=1, name='Default'`
